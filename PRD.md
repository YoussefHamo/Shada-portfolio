# Product Requirements Document (PRD) — Rifqi Muhammad Aliya Portfolio

## 1. Product Overview

A personal portfolio website for **Rifqi Muhammad Aliya** (`rifqi.dev`), a frontend developer / junior programmer. The site features a dark-themed interactive public portfolio with 3D animations, plus a password-protected admin dashboard for managing all content.

**Tech Stack:** Next.js 16 (App Router), TypeScript, Tailwind CSS, Framer Motion, Three.js / React Three Fiber, Supabase (DB, Auth, Storage), SweetAlert2.

---

## 2. Target Users

| Persona | Goals |
|---------|-------|
| **Recruiters / Hiring Managers** | View projects, skills, certificates; assess technical ability; find contact info |
| **Fellow Developers** | Explore projects, leave comments, connect via social links |
| **Admin (Rifqi)** | Login via email/password; CRUD projects, certificates, tech stack, comments; reply & pin comments |

---

## 3. Features & Pages

### 3.1 Public Site (Single-Page Layout)

| Section | Description |
|---------|-------------|
| **Welcome Screen** | Animated intro overlay (shown once per session) with staggered icon + text entrance, auto-dismisses after ~2.8s |
| **Navbar** | Fixed glassmorphism navbar with smooth-scroll links (Home, About, Portfolio, Contact). Active section detection. Mobile hamburger drawer. |
| **Hero** | Full-screen hero with headline, typing text effect, skill badges, and 3D interactive physics card (desktop only) |
| **About** | Bio with profile picture, quote, CV download, live stats (project/certificate counts) |
| **Portfolio Showcase** | Tabbed view: **Projects** (card grid with pagination), **Certificates** (clickable lightbox), **Tech Stack** (logo grid). Data cached in sessionStorage. |
| **Portfolio Detail** | `/portfolio/[id]` — Full project detail with gallery carousel, lightbox, description, tech stack, key features, Live Demo / GitHub links |
| **Contact** | Contact form (UI only), social links, and live comments section (realtime via Supabase Realtime) |

### 3.2 Admin Dashboard (All routes under `/admin`, auth-protected)

| Page | Description |
|------|-------------|
| **Login** | Email/password login via Supabase Auth |
| **Dashboard** | Stats overview: total projects, certificates, comments, pinned comments; recent comments list |
| **Projects** | CRUD: grid view, add/edit modal with title, description, live_url, github_url, technologies, key_features, multiple image upload |
| **Certificates** | CRUD: grid view, add/edit modal with title and single image upload |
| **Comments** | Manage: like/unlike, pin/unpin, reply (stored as JSON array), delete |
| **Tech Stack** | CRUD: grid view, add/edit modal with name and logo upload |

## 4. Supabase Database Schema

### 4.1 Table: `projects`

Stores portfolio projects with images, links, and metadata.

| Column | Type | Constraints | Notes |
|--------|------|-------------|-------|
| `id` | `uuid` | PK, `DEFAULT gen_random_uuid()` | |
| `title` | `text` | NOT NULL | |
| `description` | `text` | NOT NULL | |
| `live_url` | `text` | nullable | |
| `github_url` | `text` | nullable | |
| `technologies` | `text[]` | `DEFAULT '{}'` | Array of tech names |
| `key_features` | `text[]` | `DEFAULT '{}'` | Array of feature descriptions |
| `image_url` | `text` | nullable | Thumbnail image |
| `image_urls` | `jsonb` | `DEFAULT '[]'` | Array of all project images |
| `created_at` | `timestamptz` | `DEFAULT now()` | |
| `updated_at` | `timestamptz` | `DEFAULT now()` | Auto-updated via trigger |

**Index:** `idx_projects_created_at ON projects(created_at)`
**Trigger:** `update_projects_updated_at` (BEFORE UPDATE, sets `updated_at = now()`)
**RLS:** Enabled. Public SELECT policy (true). Admin writes via service_role key or authenticated-user policy.

## 6. Authentication & Authorization

- **Auth Provider:** Supabase Auth (email/password)
- **Middleware:** Next.js Middleware checks session on every `/admin/*` request; redirects to `/admin/login` if unauthenticated
- **Client-side:** Each admin page checks `supabase.auth.getSession()` on mount; redirects if no session
- **RLS:** All tables have RLS enabled. Public read access on all tables. Public insert on comments. Admin write operations use service_role key or authenticated-user RLS policies.

## 7. Non-Functional Requirements

| Requirement | Detail |
|-------------|--------|
| **Performance** | Portfolio data cached in sessionStorage with stale-while-revalidate pattern |
| **Real-time** | Comments and admin CRUD pages use Supabase Realtime subscriptions for live updates |
| **Responsive** | Tailwind responsive design; mobile hamburger nav; 3D hero hidden on mobile |
| **Animations** | Framer Motion for page transitions / entrance animations; GSAP for typing text effect |
| **Security** | Admin routes protected by middleware + client-side checks; RLS on all tables |
